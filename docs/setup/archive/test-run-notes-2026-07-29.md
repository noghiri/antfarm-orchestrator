   - **(b) Wrong exit wording — "close the window":** feature-registry and feature-design both correctly prompted the human to end the session, but told them to close the window, which would break things (it should say Ctrl+C or `/exit`). Feature-design does this fairly consistently — of all the variants, this is the most reliable/consistent stage-end behavior observed, making it the best candidate to fix first and use as the base to correct and propagate to the other stages.
   - **(c) Ask-permission-to-self-launch:** on a second feature-registry pass, instead of prompting to exit, the session asked the user for *permission* to launch the next stage itself.
   - **(d) Coordinator asks instead of exiting [needs verification]:** the coordinator session asked the user whether they wanted to start feature design, instead of just writing `next_session` and exiting per its documented job ("run stage gate checklist → validate doc approval → advance stage → write `next_session` → exit," no mention of asking).    - **(e) Full kill-and-restart instead of Ctrl+C twice:** during the L1 revision/pause flow (item 18), the coordinator told the user to fully kill everything and re-run `orchestrate.ps1` from scratch, rather than the normal Ctrl+C-twice exit that lets the harness loop continue naturally. Never self-trigger the next stage inline, never ask permission to launch it, never suggest closing the window or a full restart.
   - **Resolved (2026-08-05):** rewrote completion-signal wording across `prompts/coordinator.md` and all four stage prompts (base + assembled) — every exit point now says Ctrl+C / `/exit`, states the harness launches the next session (not "Launching..." as if the current session does it), and explicitly forbids asking permission or self-triggering.
